# ECD-SNIPR 完整分析流程与筛选标准

适用实现：v0.10.2。本文以实际代码及合同为准；只公开方法，不包含实验室名单、构建、读数或验证结果。

## 1. 核心任务与结论边界

**从明确定义的人源膜蛋白集合中，提出可追溯的抗原胞外片段方案，并指出接入 SNIPR 接收端前应核验的问题。**

构型固定为 **Antibody-Sender → Antigen-Receiver**：对侧细胞展示抗体，本系统设计靶抗原片段用于接收端的识别位置。不是设计抗体，也不是生成发送端 PDGFR–LC。公开参考架构不等于实验室实际骨架。

当前程序能回答“取哪一段、依据是什么、哪些地方需核验”。不能仅凭片段设计判断表面表达、低背景或诱导成功，也不输出未经验证的功能成功概率。

必须同时保留四个独立维度：

| 维度 | 可以给出的判断 | 不能推出的结论 |
|---|---|---|
| 候选设计 | 常规、条件性、无常规路线、核心证据不足 | 常规候选必然功能正常 |
| 核心证据复核 | 精确序列/区间是否相符；结构域是否保留；预测是否冲突 | 没发现冲突就是低风险 |
| 机制核验优先级 | 某条注释或预测为何值得重点检查 | 已预测自激活、失败概率 |
| 实验终点 | 四类读数的来源、定义、构建和条件是否有效对应 | 有阳性克隆或已做实验就是 SNIPR 成功 |

## 2. 输入、处理与输出

| 阶段 | 输入 | 确定性处理 | 主要输出 / 不足时的处理 |
|---|---|---|---|
| 定义集合 | UniProt 查询或 accession/基因名单 | 记录物种、数据库版本、检索条件、参考选择、去重和完整性 | `set_definition.json`；歧义和失败逐条保留 |
| 规范化注释 | 原始 UniProt JSON、缓存及指定参考序列 | 保留定位、拓扑、加工、结构域、证据等级和适用序列 | 逐参考 JSON；版本或 isoform 冲突不静默转移 |
| 候选生成 | 参考、可信区间、成熟加工与结构域 | 优先完整成熟形式，检查原生排除片段和结构单元 | 候选区间、序列、依据、备选；不足不造序列 |
| 逐个初筛 | 候选及检查结果 | 透明决策表；候选独立评价，按明确次序选主方案 | `protein_screening.tsv`、`candidate_plan.tsv`、FASTA |
| 核心复核 | 精确参考、候选、可选 InterPro 和三算法结果 | 独立重算序列、域保留、全长预测向片段投影 | `candidate_core_evidence.tsv`、域覆盖和缺失状态 |
| 机制核验 | 保留的注释、原生上下文、计算描述 | 区分直接区间证据、原生背景、一般序列提醒 | `receiver_risk.tsv`、信号来源、建议核验终点 |
| 可选装配 | 实际骨架、模块顺序/版本、人工批准 | 排除残留原生 SP/TM/尾，核对连接与序列 | 完整融合序列；缺项则不导出，但不阻断前述初筛 |
| 可选实验关联 | 实际构建、发送端、宿主、条件与原始读数 | 保留原字段/行/单元格，区分四终点及定义有效性 | `receiver_function.tsv`；不明字段不转成成败标签 |
| 汇总与验收 | 全部逐条记录和原始文件 | 对账、哈希、独立复算、范围完整性检查 | `summary.json`、`PI_SUMMARY.md`、总体图及绘图数据 |

### 集合口径与身份

- 默认公开查询是 `organism_id:9606 AND reviewed:true AND (keyword:"Membrane" OR keyword:"Cell membrane")`。它是“经审阅的人源膜相关参考条目”，不是所有 isoform，也不全是细胞表面蛋白；不预设固定条目数。
- 分开记录：属于膜相关集合、天然细胞表面定位是否有依据、是否进入当前设计范围。细胞器条目、多跨膜条目和未知定位不会因为难处理而消失。
- 分泌蛋白只作范围扩展，单独统计，不并入核心膜蛋白比例分母。
- accession 直接解析；基因名按人源精确查询映射并保留分页/检索依据。多匹配不能猜。重复输入保留对应关系，不重复计为独立参考。
- 可以选择数据库 canonical/reference 作为初筛参考；它不等于实验 isoform 已确认。其他 isoform 的坐标不能套到当前序列。注释中的异构体差异记录下来，但没有异构体序列时不声称已完成序列级比较。
- 输入行、gene、reference/isoform、candidate 是不同计数单位。未解析行、技术失败和范围外对象均须对账。

## 3. 候选生成与硬检查

区间统一为**所选参考上的 1-based inclusive**，长度为 `end - start + 1`；序列必须精确等于参考的 `sequence[start-1:end]`。不能让 LLM 编写候选序列或凭印象改坐标。

| 类别 | 允许的常规/条件路线 | 特别核验 |
|---|---|---|
| 单跨膜 I 型 | 有注释依据的连续成熟 ECD | 去原生 SP、TM、胞内尾；保留结构单元和表位范围 |
| 单跨膜 II 型 | 有依据的外侧区间，通常为条件性方案 | 接收端连接可能改变原来的系留方向；不是反转氨基酸序列 |
| GPI 锚定 | 有来源的成熟抗原形式 | 核对 omega 位点，保留该残基，排除其后的 GPI 信号；不能猜成熟边界 |
| 多跨膜 | 一个注释外侧区间内、有来源的外部域备选 | 不拼接多个胞外环；缺膜环境的结构/构象表位可能无法保留 |
| 成熟分泌 / shed 形式 | 有来源的 chain、加工或释放区间 | 不简单从 SP 后截到末端；注意多链、前肽和系留后上下文 |
| 多成熟产物 / 多链 | 按产物及区间分别提出有依据的方案 | 完整某个区间不等于覆盖全部成熟产物或所有抗体表位 |

**继续阻断的错误：**身份/序列/坐标错误、适用参考冲突、核心排除特征坐标不可靠、候选内残留原生注释 SP/TM/intramembrane/胞内尾/应去除的加工区段。受阻候选不被另一个可用候选“升级”。

**不做的操作：**随机滑窗、默认突变优化、无来源拼环、为了长度机械截短、给每个蛋白强制同样数量的方案、借专利补齐实际骨架、自动批准融合序列。

完整成熟形式优先；只有明确来源和理由时才生成域片段等备选。已知表位覆盖单独检查：切掉已知表位必须明示；未知表位表示未提供/未完成映射，不能写“表位保留”。缩短片段可能改变可筛选的抗体集合。

## 4. 四类初筛建议与主要候选选择

| 类别 | 必要依据 | 对实验人员的含义 |
|---|---|---|
| `standard_candidate` | 明确参考序列，正面的拓扑/区间依据，可用候选且没有触发条件性设计问题 | 有常规片段方案；不是低背景或成功构建 |
| `conditional_candidate` | 有实际、可追溯候选，但存在方向、域取舍、成熟产物、边界或原生相互作用上下文等问题 | 可以评估，但要特殊设计或重点核验 |
| `no_standard_route` | 拓扑已理解，但当前路线没有支持的可用方案 | 路线限制；不代表永远不能用 |
| `insufficient_evidence` | 身份、拓扑或关键成熟/外侧边界不足或冲突 | 核心资料不足；不是实验阴性 |

决策先分离技术失败和范围外，再处理核心证据不足，再独立评价可用候选。不能只凭“没有风险标记”给常规建议。

主方案的透明比较次序：①注释结构单元/二硫键破坏较少；②有映射时已知表位损失较少；③完整 ECD、成熟 GPI、成熟分泌、shed、域片段的形式优先次序；④稳定 candidate ID。不是总分，不按警告条数、最短长度或功能概率排序。备选仍保留理由和表位/产物范围变化。

没有历史实验、没有表位图或六类风险文献不全，不自动把有可靠边界的候选变成资料不足。风险缺失另列。可选实验室经验规则必须有来源、适用范围与理由，且只能注释或降级；未导入时写“尚未纳入”，不能声称已经由实验校准。

## 5. 核心证据加深：注释、结构域及三算法

| 方法 | 当前实际作用 | 不支持的推论 |
|---|---|---|
| UniProt | 精确参考、定位、拓扑、加工、域/重复、二硫键、糖基化及注释文本来源 | reviewed 条目中的每个特征都经实验确认 |
| InterPro/Pfam | 可选按公开 accession 取得既有域匹配；检查完整参考完全相同；列保留/切断/遗漏 | 已运行 InterProScan；family/repeat 必然是可独立折叠的域 |
| SignalP 6 | 本地完整参考的信号肽/切割预测，投影到实际候选区间 | native SP 预测能证明未知融合体分泌或表达 |
| DeepTMHMM2 | 本地完整参考逐残基拓扑及排除区段投影 | “outside” 一定是天然细胞外；就是原版 DeepTMHMM |
| IUPred2A | 完整参考逐残基无序分数及片段描述 | 无序就是自激活；参考切片等于对融合体重新预测 |
| 本地描述 / 可选 Biopython | 疏水性、复杂度、组成与理化描述及独立复核 | 聚集、蛋白酶切割、SNIPR 功能预测器 |

原始 FASTA、版本、参数、程序/数据/模型、输出均记录哈希。坐标仅在参考序列完全一致时投影。native SP/TM 在候选之外不算候选残留；预测进入候选区间则提出冲突核验，不悄悄改边界。

InterPro 的 family、domain、repeat、superfamily 分开；多个相关数据库匹配不是独立投票。不连续域匹配保留多个区间，不拼接成新序列。缺缓存、未运行、网络错误、序列版本冲突分别保留。

三算法及 InterPro 都是增强支线：缺少它们不抹去有依据的初筛方案，但不能声称已复核这些内容。要求运行的工具缺失时，该工具验收范围保持 partial。

## 6. 核验标准：哪些是阈值，哪些只是提醒

以下是当前源码的默认**核验提醒参数**，不是经过实验校准的成功/失败线：

| 项目 | 默认设置 | 意义 |
|---|---|---|
| 短 / 长片段 | `<50 aa` / `>500 aa` | 提醒表达、几何、折叠或范围核验；不自动淘汰 |
| Cys 富集 / 奇数 Cys | Cys 比例 `>=0.08`；非零奇数个另提醒 | 不证明自由巯基、聚集或错误折叠 |
| N 糖基化 | `N-X-S/T，X≠P` | 可能基序，不等于实际占位 |
| 糖基化密集 | 基序数 `>=4` 且平均 `<=50 aa/基序` | 一般提醒，不做风险投票 |
| 注释邻接容差 | 未注释间隔默认 `<=5 aa` | 标明容差使用；不能容忍真实 TM/SP 残留 |
| 局部疏水性 | Kyte–Doolittle 19 aa 窗口，均值 `>=1.6` | 不能区分埋藏疏水核、膜段与聚集 |
| 低复杂度 | Shannon 12 aa 窗口，熵 `<=2.2` | 不是 SEG，也不是无序或凝聚预测 |
| S/T/P 富集 | 30 aa 窗口，比例 `>=0.65` | 组成/连接几何提醒，非已测 O 糖基化 |
| IUPred 描述 | 统计分数 `>0.5` 的片段比例 | 无序描述，不用于功能分类 |

具体源码及单次运行冻结的规则快照优先于本文。改变参数必须创建新版结果，不能覆盖历史。

## 7. 独立的机制核验优先级

| 优先级 | 触发依据 | 解释 |
|---|---|---|
| `elevated_review_priority` | 保留区间的加工/链间关联注释、结构单元破坏，或完整区间有明确胞外自身相互作用来源 | 特异线索值得优先核验；不是已预测失败 |
| `context_dependent_review` | 原生 shedding/association 但定位或新骨架适用性未定；内源配体/Ig/糖链环境；精确预测冲突 | 需要宿主、发送端、培养条件和真实连接上下文 |
| `sequence_alert_only` | 一般疏水/组成/复杂度提醒 | 不得事后算作自激活预测命中 |
| `no_specific_signal_detected` | 实际运行的方法未找到有支持的特异线索 | 不是低风险、阴性证据或安全保证 |
| `not_assessed` | 设计受阻、序列无效或参考冲突 | 无法评价，不能并入阴性 |

注释对象必须是当前靶蛋白，不能把“与另一蛋白的同源二聚体结合”算作本蛋白自聚集；否定、胞内作用、片段外作用和语义不明记录必须排除或留待核验。当前使用保守词法/语法规则，不是全面语义理解。

加工、原生脱落、接头剪切、寡聚、聚集、培养环境干扰是分开的上下文类别。原生寡聚不等于异常聚集，原生加工不等于新接收端自激活。实际接头缺失时不能评价接头切割；不能用基因黑名单或已知失败标签暗中调整规则。

## 8. 装配与实验验证：可选但不可冒充完成

完整融合序列必须有实际骨架模块及顺序、版本、宿主/报告系统等必要元信息，实验 isoform 依据和命名人工审阅。当前支持的单信号肽/单抗原槽/单接收端 TM 架构之外不能自行发明。缺资料时仍交付候选片段和连接位置说明，但不输出猜测融合体。

实验判断单位为：**具体片段/完整接收端 × 骨架版本 × 抗体/发送端 × 条件/批次**，不是 gene。四类终点分别记录：

1. 表面表达：实际表面测量、标签位置、门控和分母；不是只看总表达。
2. 识别保留：对应抗体/发送端的结合；不能由“完整域保留”代替。
3. 背景激活：明确无刺激/对照条件下的报告读数。
4. 诱导响应：明确刺激、基线、时间点和可比读数。

`SNIPR Assay=Y` 只说明做过实验；空白是缺失，不是失败。BFP/myc/mRuby3 字段要先核对门控层级、分母、单位和刺激条件；阳性抗体克隆不等于整个接收端成功。明确 self-activation 可以记录为该来源报告的终点，但是否为有效可比较标签仍要看构建/条件与定义。

不能混合不同片段、骨架、批次或条件的同名读数。未达到匹配和语义审阅要求的记录仍保留来源，只不用于准确率计算。

## 9. 汇总、harness 与独立验收

流程为：**集合 → 注释 → 候选 → 初筛建议 → 核心证据 → 机制核验 → 逐条/总体交付 → 独立复算**。真实装配、实验关联是下游支线。

- 程序负责身份、序列切片、坐标、工具调用、决策表和统计；harness 负责状态、缓存、版本、失败隔离、重试和不可变结果。
- skill 规定边界、顺序、证据与输出；agent/LLM 负责操作协调、针对性文献与异常解释，不替代确定性检查，不自由生成序列，不审批。
- `verify-run` 验收文件哈希；`verify-predictions` 复查原始 FASTA/逐残基输出；`verify_core_evidence.py` 独立重算片段和结构域保留，避免仅验证汇总表自身一致。
- HPC 重算原始输出再导入，检查每个参考/工具的去向。已有完成结果仅在合同/哈希相符时复用；损坏或失败尝试保留，新目录重试。
- 集合获取完整、候选处理完整、指定工具全部完成、实验验证完成是不同状态。8 个或任意数量的不支持序列必须留在分母并标明，不能用“可计算部分完成”替代全范围完成。
- 图表展示“候选设计覆盖/初筛建议”，pilot 必须标为 pilot。独立复算是软件验收，不是隔离 agent 的生物学准确率。

## 10. 可重复运行入口与当前未完成项

按 [README](../README.md) 运行 `make all-checks-offline`、`build-set`、`screen`。三算法先按 [本地部署说明](local-predictors-v0100.md) 完成外部安装，再显式配置/执行；大集合使用 [HPC 说明](hpc-execution.md)。部署不会自动启动全量任务。

每次结果应交付：逐参考表、主/备选序列、风险及缺失信息、输入/参考/候选分母、完整性、图和数据、软件/数据库/参数/模型哈希以及验收日志。XLSX 仅是展示格式，不能替代 TSV/JSON/FASTA。

当前未建立通用自激活或 SNIPR 功能分类器；没有可宣称的 held-out accuracy。需要预先冻结规则、定义接受标准、取得真实构建匹配的四终点标签，并按蛋白/同源家族隔离或进行前瞻性验证。

表位覆盖、糖基化占位、完整融合体几何、特定蛋白酶/培养环境和多链依赖仍需针对性资料与实验。HPA/GTEx、药物证据、人鼠偏好不是本接收端工程初筛的硬条件，不应混入“是否可提出候选”的门槛。

公开内容仅限通用代码、合同、合成测试、公开资源方法。私有工作簿、实际构建、阳性/失败标签、回顾性对照和输出不得进入 Git；SignalP 许可证/包及任何第三方权重也不进入 Git。
